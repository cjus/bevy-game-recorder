# Project tracking

Read `docs/PRD.md` and root `status.md` before continuing recorder work. Maintain the PRD as the requirements/acceptance reference and status.md as the progress, blocker and next-step record. Distinguish implemented behavior from checks actually run and from planned consumer integration.

Keep operational setup/integration instructions in README.md and detailed validation evidence in VALIDATION.md; cross-link them from the tracking files and keep repeated commands consistent. Never mark playable output, audio isolation or A/V synchronization validated without live evidence. Update the validated implementation commit when code is tested; documentation-only commits need not refer to their own hash.
